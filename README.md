# RAG 可视化工作台

一个「真实可用 + 逐步可见」的个人 RAG 工作台。它真正跑通
上传文档 → 解析 → 清洗 → 切分 → 向量化 → 入库 → 检索 → 精排 → 组装上下文 → 流式生成
的全流程，同时在界面上逐步点亮每一步，展示**每一个步骤的中间结果**：
清洗删了什么、分块文本、向量维度与头部、粗排/精排名次对照、邻块扩展明细、
实际发给大模型的完整 Prompt，以及带可点击引用、按 Markdown 渲染的流式回答。

- 后端：Python + FastAPI（本地运行，数据全部留在本机）
- 模型服务：阿里云百炼。生成走 OpenAI 兼容接口（qwen 系列），向量 text-embedding-v3，
  精排走百炼原生接口（gte-rerank-v2）
- 向量库：本地文件持久化（numpy + JSON），重启不丢
- 前端：单页 Tailwind CDN，无需构建

## 目录结构

```
rag-workbench/
├─ app.py              # FastAPI 入口与全部路由（REST + SSE）
├─ config.py           # config.json(参数) + .env(API Key)
├─ rag/
│  ├─ loader.py        # 解析 pdf/docx/txt/md
│  ├─ cleaner.py       # 入库前清洗：规范化 / 去页码页眉 / 去重复行
│  ├─ chunker.py       # 递归字符切分 + 按标题等级切分
│  ├─ embeddings.py    # 百炼向量化
│  ├─ llm.py           # 百炼流式生成
│  ├─ rerank.py        # 百炼原生精排
│  ├─ store.py         # 本地向量库（原子落盘 / 损坏恢复 / 检索 / 邻块）
│  ├─ clients.py       # AsyncOpenAI 客户端缓存与统一关闭
│  ├─ events.py        # 步骤事件与 SSE 编码
│  ├─ logging_setup.py # 统一日志（控制台 + 轮转文件）
│  ├─ errors.py        # 带中文提示的领域异常
│  └─ pipeline.py      # 建库 / 问答 / 内容匹配三条可视化流水线
├─ static/             # 前端工作台（index.html + app.js）
├─ tests/              # pytest：向量库 / 切分 / 清洗 / 请求体边界
├─ examples/           # 内置示例文档（一键载入）
├─ data/kb/            # 运行期生成的向量库
└─ data/logs/          # 运行日志（2MB × 4 轮转）
```

## 快速开始

1. 安装依赖（国内网络建议加清华镜像）：

   ```bash
   python -m venv .venv
   source .venv/Scripts/activate        # Windows Git Bash
   pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
   ```

2. 启动（Windows 也可以直接双击根目录的 `start.bat`）：

   ```bash
   .venv/Scripts/python -m uvicorn app:app --host 127.0.0.1 --port 8000
   ```

   > 默认不开 `--reload`：开发时按需自行加上，否则每次改代码都多一次全量导入。

3. 打开 http://127.0.0.1:8000 ，
   在右上角「设置」里填入你的 [阿里云百炼 API Key](https://bailian.console.aliyun.com/) 并测试连通。

4. 点左侧「示例」一键载入 3 篇内置文档，观察**建库流水**逐步执行；
   然后在上方输入框提问，观察**问答流水**每一步实时点亮。

## 跑测试

```bash
.venv/Scripts/python -m pytest          # 84 个用例，约 3 秒
```

## 功能一览

| 区域 | 能力 |
| --- | --- |
| 知识库 | 拖拽/选择上传（≤100MB，边收边写、超限即拒）、内置示例一键载入（幂等）、逐篇删除、整体清空 |
| 建库流水 | 解析 → 清洗 → 切分 → 向量化 → 入库，每步都给出中间数据（清洗删了哪些行、每块原文、向量头部 6 维、维度与耗时） |
| 问答生成 | 粗排召回 → 精排 → 组装上下文 → 流式生成；支持多轮追问，回答按 Markdown 渲染，`[n]` 引用可点击定位到命中的原文 |
| 内容匹配 | 不生成回答，只把一段文本与知识库分块逐条比对，输出粗排/精排双列名次对照；**可勾选参与匹配的文档范围**（默认全选）；可选让模型解读匹配结果 |
| 参数 | Top-K / 相似度阈值在首页即时可调（改动即存）；召回数、精排开关、邻块窗口、切分策略等在「设置」里 |
| 会话 | 对话历史存在本地浏览器，刷新不丢；追问自动带最近几轮上文，`新对话` 清空上文 |
| 其他 | 深色 / 浅色主题（跟随系统，可手动切换并记住）、取消进行中的流程、导出当前流水为 Markdown |

## 检索链路

```
q_embed → retrieve(向量粗排，召回 recall_k 条) → rerank(精排取 top_k) → context(邻块扩展后拼 Prompt) → generate
```

- 精排关掉时 `recall_k` 无效，直接取 top_k。
- `neighbor_window` 控制邻块扩展：命中块前后各带 N 块进上下文（small-to-big），
  窗口只在本篇文档内滑动。
- 精排开启后界面会额外列出「紧随其后、被召回数截断的那几条」，
  用来判断召回数是不是设小了。
- 内容匹配可以只挑几篇文档参与比对：排名在所选范围内进行，
  没勾上的文档连「截断项」都不会出现。选 0 篇无法提交。

## 使用提示

- 切分策略/大小/重叠、嵌入模型、向量维度改动后需「清空知识库」重建
  （维度不一致会抛带中文说明的 `DimMismatch`，不再是 numpy 英文堆栈）。
- 精排开关、召回数、邻块窗口、Top-K、阈值改动**无需重建**，立即生效。
- 支持上传 .pdf / .docx / .txt / .md；旧版 .doc 与扫描版 PDF（无文字层）无法解析。
- API Key 只保存在项目本地的 `.env`，界面只显示是否已配置，不会上传任何服务器。

## 数据安全

向量库的两个文件（`meta.json` / `vectors.npy`）按行对齐。落盘走
「先写临时文件 → `os.replace` 原子替换」，所以磁盘上要么是上一份完整内容、
要么是新的一份，不会出现半截文件。

载入时如果发现文件损坏或两侧行数对不上：

- **能救就救**：行数不一致时按共同前缀截断（行是追加有序的，共同前缀必然自洽），
  只损失最后一批，而不是丢掉整库；
- **救不了就锁**：文件彻底读不出来时按空库启动，但**禁止任何写入**，
  原文件一个字节都不动，界面上给出横幅说明原因。
  备份好 `data/kb` 之后点「清空知识库」才会解锁——那是用户明确放弃原数据的动作。

`data/logs/workbench.log` 记录每一次请求、建库、问答与异常堆栈，
出问题可以事后追查，不用只靠前端那一眼。

## 常见问题

- **问答/建库报「未配置 API Key」**：先到「设置」里填写并点“测试连接”。
- **检索总是 0 命中**：确认知识库非空（看顶部统计芯片），并检查嵌入维度等参数一致后重建库。
- **答案质量差**：先看“向量粗排召回”的分数，再看精排前后的名次变化；
  接着展开“组装上下文”核对注入的参考资料，最后才考虑换更强的生成模型。
- **追问答非所问**：追问只带最近几轮上文，且明确要求「引用编号只算本轮资料」；
  如果问题依赖更早的对话，点历史里的「填入输入框」把上下文重新提一遍更稳。
- **左侧出现红色横幅**：说明向量库文件有问题，按横幅里的提示先备份再处理，别直接删 `data/kb`。
